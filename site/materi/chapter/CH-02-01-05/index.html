    Dasar Shell Scripting¶

    Identitas chapter

    ID: CH-02-01-05 · Kategori/modul: CAT-02 / MOD-02-01 · Estimasi: 150 menit · Lingkungan: lab lokal (VM) · Lihat di dashboard

    Catatan verifikasi

    Skrip contoh dijalankan pada 2026-10-13 di Ubuntu 24.04.3 LTS (WSL2) dengan GNU bash 5.2.21. shellcheck tidak terpasang pada lingkungan uji, sehingga tidak dijalankan.

    1. Ringkasan¶

    Anda menulis skrip bash sederhana yang aman: variabel, kondisi, loop, dan exit status. Skrip diagnostik kecil akan menjadi bahan baku deliverable Level 1 (skrip diagnostik dasar).

    2. Tujuan Pembelajaran¶

    1. Menulis skrip bash sederhana yang aman.
    2. Memakai variabel, kondisi, loop, dan exit status.

    3. Prasyarat¶

    • CH-02-01-04 — manajemen paket; Anda nyaman mengetik perintah dan mengatur izin berkas.

    4. Materi Teori¶

    4.1 Struktur skrip¶

    • Baris pertama (shebang) #!/usr/bin/env bash memilih interpreter.
    • Berkas harus dapat dieksekusi (chmod +x).
    • Setiap perintah mengembalikan exit status: 0 sukses, bukan nol gagal. Nilai terakhir ada di $?.

    4.2 Mode aman¶

    set -euo pipefail
    Opsi Efek
    -e Berhenti saat sebuah perintah gagal
    -u Menganggap variabel yang belum diisi sebagai galat
    -o pipefail Pipeline gagal jika salah satu bagiannya gagal

    Opsi ini bukan jaminan penuh; tetap uji jalur gagal skrip Anda.

    4.3 Variabel, kondisi, loop¶

    • Variabel: nama="nilai", dipakai sebagai "$nama". Selalu beri tanda kutip agar spasi tidak memecah nilai.
    • Parameter bawaan: "${1:-example.com}" memakai argumen pertama atau nilai default.
    • Kondisi: if ...; then ...; else ...; fi.
    • Loop: for item in a b c; do ...; done.
    • Gunakan test/[ ... ] atau [[ ... ]] untuk perbandingan.

    4.4 Kebiasaan aman¶

    • Kutip semua ekspansi variabel.
    • Jangan menjalankan input yang tak tepercaya sebagai perintah.
    • Tulis galat ke stderr (>&2) dan keluar dengan status bukan nol.
    • Jangan menaruh kata sandi di dalam skrip.
    • Periksa skrip dengan shellcheck jika terpasang (opsional).

    5. Praktik dan Implementasi¶

    Checklist persiapan

    • Saya berada di direktori latihan, bukan di /etc.

    Langkah

    1. Tulis skrip pemeriksa DNS cek.sh (bagian 6).
    2. Jalankan dengan argumen default, dengan nama yang tidak ada, dan amati exit status.
    3. Tambahkan loop untuk beberapa nama host.
    4. (Opsional) Pasang shellcheck dengan sudo apt install shellcheck dan periksa skrip Anda.

    6. Perintah Linux¶

    Skrip (diuji):

    #!/usr/bin/env bash
set -euo pipefail
host_tujuan="${1:-example.com}"
if getent hosts "$host_tujuan" >/dev/null; then
  echo "DNS OK: $host_tujuan"
else
  echo "DNS GAGAL: $host_tujuan" >&2
  exit 1
fi

    Menjalankan:

    # pengguna biasa
chmod +x cek.sh
./cek.sh;                    echo "exit=$?"
./cek.sh tidak-ada.invalid;  echo "exit=$?"

    Output yang diamati pada uji:

    DNS OK: example.com
exit=0
DNS GAGAL: tidak-ada.invalid
exit=1

    Loop (konsep; belum dijalankan terpisah):

    for host in example.com example.org; do
  ./cek.sh "$host" || echo "periksa $host"
done

    7. Konfigurasi¶

    Tidak ada berkas konfigurasi sistem. Simpan skrip Anda di direktori kerja sendiri (misalnya ~/bin), bukan di /etc.

    8. Verifikasi¶

    • Skrip mengembalikan exit=0 untuk host yang resolve dan exit=1 untuk host yang tidak.
    • Pesan galat muncul di stderr (coba ./cek.sh tidak-ada.invalid 2>/dev/null dan lihat tidak ada pesan galat).
    • bash -n cek.sh tidak mengeluarkan galat sintaks.

    9. Troubleshooting¶

    Gejala Penyebab Tindakan
    Permission denied saat menjalankan Belum chmod +x chmod +x cek.sh
    unbound variable Variabel belum diisi dengan -u aktif Beri default ${VAR:-nilai} atau isi variabel
    Skrip berhenti tanpa pesan -e menghentikan pada perintah gagal Tambahkan pesan galat dan tangani kegagalan
    Spasi memecah argumen Variabel tak dikutip Kutip "$var"

    10. Security Review¶

    • Kutip variabel dan hindari eval.
    • Jangan menyimpan kredensial dalam skrip atau riwayat perintah.
    • Skrip yang dijalankan dengan sudo harus dapat diubah hanya oleh root, atau pemilik berkas bisa menaikkan haknya.

    11. Latihan¶

    1. Ubah cek.sh agar menerima banyak argumen dan melaporkan semuanya.
    2. Tambahkan pemeriksaan bahwa ss tersedia sebelum dipakai.
    3. Tulis skrip yang mencetak "OK" jika disk root kurang dari 80% penuh (petunjuk: df).

    12. Assessment¶

    1. Apa arti exit status 0?
    2. Apa fungsi set -euo pipefail?
    3. Mengapa variabel harus dikutip?
    4. Bagaimana mengirim pesan ke stderr?

    Kunci singkat. (1) Sukses. (2) Berhenti saat gagal, tolak variabel kosong, dan pipeline gagal bila bagiannya gagal. (3) Mencegah pemecahan kata dan globbing. (4) >&2.

    13. Checklist Kelulusan¶

    • Saya dapat menulis, menjalankan, dan menguji skrip kecil.
    • Saya menguji jalur sukses dan gagal.
    • Skrip saya tidak berisi kredensial.
