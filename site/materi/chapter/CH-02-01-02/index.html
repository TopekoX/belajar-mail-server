    Navigasi Filesystem dan Hierarki Direktori¶

    Identitas chapter

    ID: CH-02-01-02 · Kategori/modul: CAT-02 / MOD-02-01 · Estimasi: 90 menit · Lingkungan: lab lokal (VM) · Lihat di dashboard

    Catatan verifikasi

    Perintah find, cp, mv, chmod, dan stat dijalankan pada 2026-10-13 di Ubuntu 24.04.3 LTS (WSL2) di direktori sementara yang kemudian dihapus. Perintah yang menyentuh /etc, /var, atau /srv hanya dibaca, tidak diubah.

    1. Ringkasan¶

    Anda berpindah antar direktori, melihat dan mencari berkas, serta menyalin dan memindahkannya dengan aman. Anda juga mengenal tata letak direktori standar Linux (FHS) yang akan sering muncul saat mengonfigurasi mail server.

    2. Tujuan Pembelajaran¶

    1. Menavigasi filesystem dan memahami FHS.
    2. Mencari berkas dan mengelolanya dengan aman.

    3. Prasyarat¶

    • CH-02-01-01 — konsep Linux dan Ubuntu Server.

    4. Materi Teori¶

    4.1 Satu pohon direktori¶

    Linux memakai satu pohon yang berakar di /. Tidak ada huruf drive. Perangkat penyimpanan tambahan dipasang (mount) pada suatu direktori.

    4.2 Hierarki penting (FHS)¶

    Direktori Isi Relevansi mail server
    /etc Konfigurasi sistem dan layanan Konfigurasi Postfix/Dovecot kelak
    /var Data yang berubah: log, antrean, spool /var/log, /var/spool
    /srv Data untuk layanan yang disajikan server Opsi lokasi data layanan
    /home Direktori pengguna Konfigurasi pribadi
    /usr Program dan pustaka Biner terpasang oleh paket
    /tmp Berkas sementara Dapat ditulis semua pengguna

    4.3 Path absolut dan relatif¶

    Path absolut diawali / (/etc/hosts). Path relatif dihitung dari direktori kerja (./demo/a, ../b). ~ menunjuk ke direktori home Anda.

    4.4 Berhati-hati dengan perintah yang mengubah¶

    cp, mv, dan terutama rm tidak punya tempat sampah. Biasakan memeriksa dulu dengan ls dan gunakan tanda -i (konfirmasi) saat ragu. Hindari rm -rf dengan path yang dibentuk dari variabel kosong.

    5. Praktik dan Implementasi¶

    Checklist persiapan

    • Saya login sebagai pengguna biasa.
    • Saya bekerja di direktori sementara, bukan di /etc atau /var.

    Langkah

    1. Buat direktori latihan dan lihat strukturnya.
    2. Salin dan pindahkan berkas, lalu cari dengan find.
    3. Baca (tanpa mengubah) isi /etc dan /var/log.
    4. Hapus direktori latihan setelah selesai.

    6. Perintah Linux¶

    # pengguna biasa
cd "$(mktemp -d)"          # pindah ke direktori sementara
pwd                         # tampilkan direktori kerja
mkdir -p demo/a demo/b      # buat direktori (beserta induknya)
echo hi > demo/a/f.txt      # buat berkas kecil
cp demo/a/f.txt demo/b/     # salin
find demo -type f -name '*.txt'
mv demo/b/f.txt demo/b/g.txt   # ubah nama
ls demo/b

    Output yang diamati pada uji:

    demo/a/f.txt
demo/b/f.txt
g.txt

    Menelusuri direktori penting (hanya baca):

    # pengguna biasa
ls /etc | head
ls -l /var/log | head

    Membersihkan:

    # pengguna biasa — pastikan Anda berada di direktori sementara dari mktemp
cd ~ && rm -r -- "<DIREKTORI-SEMENTARA>"

    Ganti <DIREKTORI-SEMENTARA> dengan path yang ditampilkan pwd sebelumnya. Periksa dulu path-nya sebelum menghapus.

    Perintah Fungsi
    pwd Menampilkan direktori kerja
    ls, ls -l Mendaftar isi direktori, -l menampilkan detail
    cd Berpindah direktori
    mkdir -p Membuat direktori dan induknya
    cp Menyalin
    mv Memindahkan atau mengganti nama
    find Mencari berkas berdasarkan kriteria

    7. Konfigurasi¶

    Chapter ini membahas lokasi, bukan isi konfigurasi. Anda hanya mengenali bahwa konfigurasi layanan umumnya ada di /etc, log di /var/log, dan data layanan di /var atau /srv.

    8. Verifikasi¶

    • find demo -type f -name '*.txt' menampilkan dua berkas sebelum mv.
    • Setelah mv, ls demo/b menampilkan g.txt.
    • Anda dapat menyebutkan fungsi /etc, /var, /srv, dan /tmp tanpa melihat catatan.

    9. Troubleshooting¶

    Gejala Penyebab Tindakan
    No such file or directory Path salah atau salah ketik Periksa dengan pwd dan ls; gunakan Tab untuk melengkapi
    Permission denied Tidak punya izin Lihat CH-02-01-03; jangan langsung memakai sudo
    Berkas terhapus tak sengaja rm tidak punya tempat sampah Pulihkan dari snapshot atau backup; biasakan konfirmasi

    10. Security Review¶

    • Jangan bereksperimen langsung di /etc pada lab tanpa snapshot.
    • Hindari rm -rf dengan variabel yang mungkin kosong.
    • Jangan membuat berkas yang menyimpan kata sandi di /tmp karena dapat dibaca pengguna lain.

    11. Latihan¶

    1. Buat struktur proyek/{docs,src,tmp} dengan satu perintah mkdir -p.
    2. Cari semua berkas .conf di bawah /etc yang dapat Anda baca dan hitung jumlahnya.
    3. Jelaskan perbedaan path absolut dan relatif dengan dua contoh.

    12. Assessment¶

    1. Apa isi /etc dan /var?
    2. Apa beda cp dan mv?
    3. Mengapa rm -rf perlu hati-hati?
    4. Apa arti ~?

    Kunci singkat. (1) Konfigurasi dan data yang berubah. (2) cp menggandakan, mv memindah atau mengganti nama. (3) Tidak ada tempat sampah dan dapat menghapus rekursif. (4) Direktori home pengguna.

    13. Checklist Kelulusan¶

    • Saya dapat berpindah, membuat, menyalin, memindah, dan mencari berkas.
    • Saya hafal fungsi direktori FHS utama.
    • Saya tahu risiko rm.
