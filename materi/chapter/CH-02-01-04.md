# Manajemen Paket dengan APT

!!! info "Identitas chapter"
    **ID:** `CH-02-01-04` · **Kategori/modul:** CAT-02 / MOD-02-01 · **Estimasi:** 90 menit · **Lingkungan:** lab lokal (VM) · [Lihat di dashboard](../../../#CH-02-01-04)

!!! note "Catatan verifikasi"
    Pada 2026-10-13 di Ubuntu 24.04.3 LTS (WSL2) hanya perintah baca-saja yang dijalankan: `apt-cache policy`, `dpkg -s`, dan `dpkg -L`. Perintah yang mengubah sistem (`apt update`, `apt install`, `apt remove`) **belum dijalankan** penulis.

## 1. Ringkasan

Anda memasang, memperbarui, dan menghapus paket dengan APT, serta memeriksa versi dan asal paket. Seluruh komponen mail server nanti (Postfix, Dovecot) dipasang dengan cara ini.

## 2. Tujuan Pembelajaran

1. Memasang, memperbarui, dan menghapus paket.
2. Memeriksa versi dan asal paket.

## 3. Prasyarat

- `CH-02-01-03` — hak `sudo` dan least privilege.

## 4. Materi Teori

### 4.1 Paket dan repositori

Paket (`.deb`) berisi program, konfigurasi bawaan, dan metadata dependensi. **APT** mengunduh paket dari repositori yang didaftarkan di `/etc/apt/sources.list.d/`, menyelesaikan dependensi otomatis, dan memverifikasi tanda tangan. `dpkg` adalah alat tingkat rendah untuk paket terpasang.

### 4.2 Perintah utama

| Perintah | Fungsi |
|---|---|
| `apt update` | Memperbarui daftar paket dari repositori (belum mengubah paket terpasang) |
| `apt upgrade` | Memperbarui paket terpasang |
| `apt install <paket>` | Memasang paket beserta dependensinya |
| `apt remove <paket>` | Menghapus paket, konfigurasi dipertahankan |
| `apt purge <paket>` | Menghapus paket dan konfigurasinya |
| `apt-cache policy <paket>` | Menampilkan versi terpasang, kandidat, dan asal |
| `dpkg -s <paket>` | Status dan versi paket terpasang |
| `dpkg -L <paket>` | Daftar berkas yang dipasang paket |

### 4.3 Praktik aman

- Jalankan `apt update` sebelum `apt install` agar daftar paket mutakhir.
- Baca daftar perubahan yang akan terjadi sebelum menjawab konfirmasi.
- Pasang hanya dari repositori resmi Ubuntu pada tahap ini.
- Jangan memasang paket yang tidak Anda butuhkan: setiap layanan menambah permukaan serangan.
- Snapshot sebelum pembaruan besar.

## 5. Praktik dan Implementasi

**Checklist persiapan**

- [ ] Snapshot VM terbaru tersedia.
- [ ] VM terhubung ke internet (adapter NAT).

**Langkah**

1. Periksa versi dan asal sebuah paket yang sudah terpasang.
2. Perbarui daftar paket dan lihat apa yang dapat ditingkatkan.
3. Pasang satu paket kecil yang tidak berbahaya (mis. `tree`), pakai, lalu hapus.

## 6. Perintah Linux

Baca-saja (diuji):

```bash
# pengguna biasa
apt-cache policy curl
dpkg -s curl | grep -E '^(Package|Version)'
dpkg -L curl | head -3
```

Output yang diamati pada uji:

```text
curl:
  Installed: 8.5.0-2ubuntu10.9
  Candidate: 8.5.0-2ubuntu10.9
Package: curl
Version: 8.5.0-2ubuntu10.9
/.
/usr
/usr/bin
```

Mengubah sistem **(belum dijalankan penulis — hanya di VM lab)**:

```bash
# root melalui sudo
sudo apt update
apt list --upgradable
sudo apt install tree
sudo apt remove tree
```

## 7. Konfigurasi

Sumber paket berada di `/etc/apt/sources.list.d/`. Chapter ini tidak mengubahnya. Lihat isinya hanya untuk dibaca:

```bash
# pengguna biasa
ls /etc/apt/sources.list.d/
```

Pada Ubuntu 24.04 berkas sumber umumnya berformat deb822 (`.sources`); periksa dokumentasi sebelum menambahkan repositori pihak ketiga.

## 8. Verifikasi

- `apt-cache policy <paket>` menunjukkan `Installed` dan `Candidate`.
- Setelah `apt install tree`, `command -v tree` menampilkan path-nya; setelah `apt remove`, perintah tidak ditemukan.

## 9. Troubleshooting

| Gejala | Penyebab | Tindakan |
|---|---|---|
| `Unable to locate package` | Daftar belum diperbarui atau nama salah | `sudo apt update`; periksa nama dengan `apt-cache search` |
| `Could not get lock` | Proses APT lain berjalan | Tunggu proses selesai; jangan menghapus berkas lock |
| Gagal unduh | Tidak ada jaringan/DNS | Uji dengan `CH-02-03-02` |
| Dependensi rusak | Pemasangan terputus | `sudo apt --fix-broken install` setelah memahami penyebab |

## 10. Security Review

- Hanya pasang dari sumber yang tepercaya; pahami asal paket lewat `apt-cache policy`.
- Terapkan pembaruan keamanan secara rutin di produksi, setelah diuji di lab.
- Hindari skrip `curl | sudo bash` yang tidak diperiksa.

## 11. Latihan

1. Bandingkan `Installed` dan `Candidate` untuk tiga paket.
2. Pasang dan hapus satu paket kecil di VM lab; catat berkas yang dibuat (`dpkg -L`).
3. Jelaskan beda `remove` dan `purge`.

## 12. Assessment

1. Apa yang dilakukan `apt update`?
2. Apa beda `apt remove` dan `apt purge`?
3. Bagaimana memeriksa asal sebuah paket?

**Kunci singkat.** (1) Memperbarui daftar paket, bukan paket terpasang. (2) `purge` ikut menghapus konfigurasi. (3) `apt-cache policy <paket>`.

## 13. Checklist Kelulusan

- [ ] Saya dapat memeriksa versi dan asal paket.
- [ ] Saya membuat snapshot sebelum pembaruan besar.
