# Proses, Socket, dan Port Listening

!!! info "Identitas chapter"
    **ID:** `CH-02-02-02` · **Kategori/modul:** CAT-02 / MOD-02-02 · **Estimasi:** 90 menit · **Lingkungan:** lab lokal (VM) · [Lihat di dashboard](../../../#CH-02-02-02)

!!! note "Catatan verifikasi"
    Pada 2026-10-13 di Ubuntu 24.04.3 LTS (WSL2): `ps`, `ss -ltn`, dan `ss -ltnp` dijalankan sebagai pengguna biasa. `lsof -nP -iTCP -sTCP:LISTEN` dijalankan tetapi tidak menampilkan baris apa pun tanpa hak root; `top` tidak dijalankan.

## 1. Ringkasan

Anda mengidentifikasi proses yang berjalan dan port yang sedang listening, lalu menghubungkan setiap port terbuka dengan service pemiliknya. Kemampuan ini dipakai untuk memastikan hanya port yang diinginkan yang terbuka pada mail server.

## 2. Tujuan Pembelajaran

1. Mengidentifikasi proses dan socket yang listening.
2. Menghubungkan port terbuka dengan service pemiliknya.

## 3. Prasyarat

- `CH-02-02-01` — systemd dan manajemen service.

## 4. Materi Teori

### 4.1 Proses

Setiap program berjalan sebagai proses dengan PID, pemilik, dan perintah. Proses induk memulai proses anak; PID 1 (`systemd`) adalah induk semuanya.

| Perintah | Fungsi |
|---|---|
| `ps -eo pid,user,comm` | Daftar proses dengan kolom pilihan |
| `ps -p <PID> -o ...` | Informasi satu proses |
| `top` | Pantauan proses interaktif (keluar dengan `q`) |

### 4.2 Socket dan port

Service jaringan membuka *socket* pada alamat IP dan port. Status `LISTEN` berarti menunggu koneksi masuk. Alamat pendengar menentukan siapa yang bisa terhubung:

| Alamat | Arti |
|---|---|
| `127.0.0.1` / `::1` | Hanya dari host itu sendiri |
| `0.0.0.0` / `[::]` | Semua antarmuka IPv4 / IPv6 |
| Alamat IP tertentu | Hanya antarmuka tersebut |

Layanan yang seharusnya internal (misalnya database) tidak boleh listen di `0.0.0.0` tanpa alasan.

### 4.3 Perintah utama

| Perintah | Fungsi |
|---|---|
| `ss -ltn` | Socket TCP LISTEN, numerik |
| `ss -ltnp` | Sama, plus proses pemilik (informasi proses penuh butuh hak root) |
| `ss -tuln` | TCP dan UDP yang listening |
| `lsof -nP -iTCP -sTCP:LISTEN` | Alternatif; hasil lengkap butuh hak root |

Port mail yang lazim akan Anda lihat nanti: 25, 465, 587 (SMTP), 143 dan 993 (IMAP), 110 dan 995 (POP3).

## 5. Praktik dan Implementasi

**Checklist persiapan**

- [ ] Saya paham perbedaan `127.0.0.1` dan `0.0.0.0`.

**Langkah**

1. Daftar port TCP yang listening.
2. Cari proses pemilik setiap port dengan `ss -ltnp` (pakai `sudo` untuk hasil lengkap).
3. Cocokkan tiap port dengan service di `systemctl`.
4. Catat port yang tidak Anda kenal untuk diselidiki.

## 6. Perintah Linux

Diuji sebagai pengguna biasa:

```bash
# pengguna biasa
ss -ltn
ps -eo pid,user,comm --sort=pid | head -3
ps -p 1 -o comm=
```

Contoh output pada uji (WSL2 hanya punya DNS stub lokal; VM server akan berbeda):

```text
State  Recv-Q Send-Q Local Address:Port Peer Address:Port
LISTEN 0      4096   127.0.0.53%lo:53        0.0.0.0:*
LISTEN 0      4096      127.0.0.54:53        0.0.0.0:*
    PID USER     COMMAND
      1 root     systemd
systemd
```

Dengan informasi proses (di VM lab, **belum dijalankan penulis dengan sudo**):

```bash
# root melalui sudo
sudo ss -ltnp
sudo lsof -nP -iTCP -sTCP:LISTEN
```

## 8. Verifikasi

- Setiap baris `LISTEN` dapat dijelaskan: port, alamat, dan service pemiliknya.
- Tidak ada port tak dikenal yang listening di `0.0.0.0` pada VM lab bersih.

## 9. Troubleshooting

| Gejala | Penyebab | Tindakan |
|---|---|---|
| Kolom proses kosong | Tidak punya hak untuk melihat proses lain | Gunakan `sudo ss -ltnp` |
| Port seharusnya listening tetapi tidak ada | Service mati atau gagal bind | `systemctl status`, `journalctl -u` |
| `Address already in use` | Port dipakai proses lain | Temukan pemiliknya dengan `ss -ltnp` |
| `lsof` tidak menampilkan apa pun | Tanpa root | Gunakan `sudo` |

## 10. Security Review

- Setiap port listening adalah permukaan serangan; tutup yang tidak diperlukan.
- Layanan internal sebaiknya listen di `127.0.0.1` atau antarmuka privat.
- Port terbuka di host belum tentu terjangkau dari luar (tergantung firewall, `CH-02-03-03`), tetapi jangan mengandalkan firewall saja.

## 11. Latihan

1. Buat tabel: port, alamat listen, proses, dan service.
2. Jalankan sebuah server sementara di port tinggi (mis. `python3 -m http.server 8080 --bind 127.0.0.1` di VM lab), temukan di `ss`, lalu hentikan dengan Ctrl+C.
3. Jelaskan mengapa alamat `127.0.0.1` lebih aman daripada `0.0.0.0` untuk layanan internal.

## 12. Assessment

1. Apa arti status `LISTEN`?
2. Apa beda listen di `127.0.0.1` dan `0.0.0.0`?
3. Bagaimana mengetahui proses pemilik sebuah port?
4. Mengapa `ss -ltnp` butuh `sudo` untuk hasil lengkap?

**Kunci singkat.** (1) Menunggu koneksi masuk. (2) `127.0.0.1` hanya lokal; `0.0.0.0` semua antarmuka. (3) `sudo ss -ltnp`. (4) Informasi proses milik pengguna lain dilindungi.
