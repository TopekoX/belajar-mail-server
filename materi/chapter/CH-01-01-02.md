# Menyiapkan Lingkungan Lab (VM dan Snapshot)

!!! info "Identitas chapter"
    **ID:** `CH-01-01-02` · **Kategori/modul:** CAT-01 / MOD-01-01 · **Estimasi:** 120 menit · **Lingkungan:** lab lokal (VM) · [Lihat di dashboard](../../../#CH-01-01-02)

!!! warning "Status verifikasi"
    Prosedur hypervisor di bawah **belum dijalankan** oleh penulis dalam pembuatan materi ini. Langkah-langkah bersifat umum dan lintas hypervisor; ikuti dokumentasi hypervisor yang Anda pakai dan catat versi Anda sendiri.

## 1. Ringkasan

Anda membuat VM Ubuntu Server 24.04 LTS sebagai lab, memberinya sumber daya yang memadai, dan membuat snapshot awal yang terbukti dapat dipulihkan. Lab yang bisa dipulihkan membuat Anda berani bereksperimen.

## 2. Tujuan Pembelajaran

1. Membuat VM lab dengan sumber daya yang memadai.
2. Membuat dan memulihkan snapshot sebelum perubahan besar.
3. Memisahkan lab dari jaringan produksi.

## 3. Prasyarat

- `CH-01-01-01` — peta belajar.
- Komputer host dengan virtualisasi aktif di BIOS/UEFI dan ruang disk yang cukup.

## 4. Materi Teori

### 4.1 Mengapa VM

VM mengisolasi eksperimen dari komputer utama dan dapat dikembalikan ke kondisi semula. Untuk mail server, VM juga memungkinkan jaringan lab terpisah sehingga uji kirim email tidak keluar ke internet secara tidak sengaja.

### 4.2 Hypervisor yang lazim

Pilih salah satu: VirtualBox, KVM (di Linux), atau VMware. Konsepnya sama: *host* menjalankan *guest*, dan guest memakai disk virtual dan adapter jaringan virtual.

### 4.3 Sumber daya yang disarankan

Angka ini saran awal untuk lab, bukan syarat resmi; sesuaikan dengan host Anda.

| Sumber daya | Saran awal lab |
|---|---|
| CPU | 2 vCPU |
| RAM | 2 GB (4 GB jika menjalankan webmail dan antispam kelak) |
| Disk | 20 GB atau lebih |
| Jaringan | Satu adapter NAT untuk akses internet (unduh paket) dan satu adapter host-only atau internal untuk lab |

### 4.4 Mode jaringan VM

| Mode | Fungsi | Penggunaan lab |
|---|---|---|
| NAT | VM keluar lewat IP host; tidak dapat diakses langsung dari luar | Mengunduh paket |
| Host-only / internal | VM hanya terhubung ke host atau sesama VM | Percobaan mail flow tertutup, SSH dari host |
| Bridged | VM mendapat IP di jaringan fisik | Hindari pada lab awal agar tidak terekspos ke jaringan nyata |

### 4.5 Snapshot

Snapshot menyimpan keadaan disk (dan opsional memori) pada satu titik. Aturan praktis:

- Buat snapshot **sebelum** perubahan besar.
- Beri nama deskriptif, mis. `01-instalasi-bersih`.
- Snapshot bukan backup: ia hidup bersama disk VM dan tidak melindungi dari kerusakan disk host.
- Uji pemulihan sekali agar Anda yakin prosedurnya berjalan.

## 5. Praktik dan Implementasi

**Checklist persiapan**

- [ ] Virtualisasi aktif di BIOS/UEFI.
- [ ] Ruang disk host cukup (minimal 25 GB bebas).
- [ ] ISO Ubuntu Server 24.04 LTS diunduh dari situs resmi Ubuntu.

**Langkah (konsep, ikuti menu hypervisor Anda)**

1. Unduh ISO Ubuntu Server dari [ubuntu.com/download/server](https://ubuntu.com/download/server) dan periksa checksum SHA256 sesuai petunjuk di halaman unduhan.
2. Buat VM baru: tipe Linux/Ubuntu 64-bit, alokasikan sumber daya sesuai 4.3, pasang ISO.
3. Atur adapter jaringan sesuai 4.4.
4. Jalankan installer. Buat satu pengguna biasa dengan kata sandi kuat (jangan dipakai ulang dari akun lain) dan aktifkan paket OpenSSH server bila ditawarkan.
5. Setelah instalasi, restart VM dan login sebagai pengguna biasa.
6. Matikan VM (*shutdown*), lalu buat snapshot bernama `01-instalasi-bersih`.
7. Nyalakan VM, buat perubahan kecil (mis. berkas `uji.txt` di home), matikan, lalu pulihkan snapshot dan pastikan berkas itu hilang.

## 6. Perintah Linux

Tidak ada perintah wajib. Setelah login Anda boleh memeriksa versi dengan:

```bash
# pengguna biasa — belum dijalankan penulis di VM server
lsb_release -a
```

## 7. Konfigurasi

Tidak ada berkas konfigurasi pada chapter ini.

## 8. Verifikasi

- VM menyala dan Anda dapat login sebagai pengguna biasa.
- `lsb_release -a` (atau `cat /etc/os-release`) menampilkan Ubuntu 24.04 LTS.
- Snapshot `01-instalasi-bersih` ada.
- Pemulihan snapshot terbukti mengembalikan keadaan awal (berkas `uji.txt` hilang).

## 9. Troubleshooting

| Gejala | Penyebab umum | Tindakan |
|---|---|---|
| VM 64-bit tidak mau jalan | Virtualisasi nonaktif di BIOS/UEFI | Aktifkan Intel VT-x / AMD-V |
| VM lambat atau macet | RAM/CPU terlalu kecil | Naikkan alokasi dalam batas host |
| VM tidak dapat dijangkau dari host | Mode jaringan tidak sesuai | Tambahkan adapter host-only |
| Disk penuh saat instalasi | Ukuran disk terlalu kecil | Perbesar disk virtual |

## 10. Security Review

- Pisahkan lab dari jaringan produksi; hindari mode bridged pada tahap awal.
- Jangan memakai kata sandi dari akun nyata untuk VM lab.
- Jangan menyimpan kunci privat atau kredensial nyata di dalam snapshot yang dibagikan.
- Jangan membuka port VM ke internet pada tahap ini.

## 11. Latihan

1. Buat VM sesuai bagian 5 dan buat snapshot awal.
2. Ubah sesuatu, pulihkan snapshot, dan catat hasilnya.
3. Jelaskan mengapa snapshot bukan pengganti backup.

## 12. Assessment

1. Apa perbedaan mode NAT dan host-only?
2. Kapan snapshot sebaiknya dibuat?
3. Mengapa mode bridged dihindari pada lab awal?
4. Apa risiko mengandalkan snapshot sebagai satu-satunya perlindungan data?

**Kunci singkat.** (1) NAT untuk keluar ke internet melalui host; host-only hanya untuk jaringan internal host–VM. (2) Sebelum perubahan besar. (3) VM terekspos ke jaringan nyata. (4) Snapshot hidup di disk yang sama dan tidak melindungi dari kerusakan host.

## 13. Checklist Kelulusan

- [ ] VM Ubuntu Server 24.04 LTS berjalan.
- [ ] Snapshot awal ada dan terbukti dapat dipulihkan.
- [ ] Jaringan lab terpisah dari produksi.
- [ ] Tidak ada kredensial nyata yang tersimpan.
