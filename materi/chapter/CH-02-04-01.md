# Administrasi Server dengan SSH

!!! info "Identitas chapter"
    **ID:** `CH-02-04-01` · **Kategori/modul:** CAT-02 / MOD-02-04 (SSH) · **Estimasi:** 120 menit · **Lingkungan:** lab lokal (VM) · [Lihat di dashboard](../../../#CH-02-04-01)

!!! note "Catatan verifikasi"
    Pada 2026-10-13 di Ubuntu 24.04.3 LTS (WSL2) dijalankan `ssh -V` dan `ssh-keygen -t ed25519` di berkas sementara (kunci langsung dihapus). **Server SSH tidak terpasang** di lingkungan uji, sehingga `ssh` ke host, `ssh-copy-id`, `scp`, dan konfigurasi `sshd` **belum dijalankan** penulis.

## 1. Ringkasan

Anda mengakses server dengan kunci SSH, menyalin berkas, dan menjalankan perintah jarak jauh dengan aman. Ini penutup Level 1 dan bekal untuk mengelola server dari jarak jauh pada Level 3.

## 2. Tujuan Pembelajaran

1. Mengakses server dengan kunci SSH.
2. Menyalin berkas dan menjalankan perintah jarak jauh dengan aman.

## 3. Prasyarat

- `CH-02-03-04` — diagnosis koneksi; Anda juga perlu pemahaman firewall dari `CH-02-03-03` agar port 22 dapat dijangkau.

## 4. Materi Teori

### 4.1 Cara kerja SSH

SSH menyediakan sesi terenkripsi ke server (port TCP 22 secara default). Klien memverifikasi identitas server lewat *host key* (disimpan di `~/.ssh/known_hosts` pada kunjungan pertama) dan server memverifikasi klien lewat kata sandi atau **kunci publik**.

### 4.2 Autentikasi kunci

- **Kunci privat** (mis. `id_ed25519`) tetap di komputer Anda dan tidak pernah dibagikan.
- **Kunci publik** (`id_ed25519.pub`) ditaruh di server pada `~/.ssh/authorized_keys`.
- Kunci diberi *passphrase* agar aman jika berkas tercuri.
- Izin: kunci privat `600`, direktori `~/.ssh` `700`.

### 4.3 Perintah utama

| Perintah | Fungsi |
|---|---|
| `ssh-keygen -t ed25519` | Membuat pasangan kunci |
| `ssh-copy-id <pengguna>@<host>` | Menyalin kunci publik ke server |
| `ssh <pengguna>@<host>` | Login interaktif |
| `ssh <pengguna>@<host> '<perintah>'` | Menjalankan satu perintah jarak jauh |
| `scp <berkas> <pengguna>@<host>:<tujuan>` | Menyalin berkas lewat SSH |

### 4.4 Mengeraskan sshd

Pengaturan server SSH ada di `/etc/ssh/sshd_config` dan `/etc/ssh/sshd_config.d/`. Praktik umum: nonaktifkan login root langsung, nonaktifkan kata sandi setelah kunci terbukti bekerja. **Jangan menonaktifkan autentikasi kata sandi sebelum login dengan kunci diuji pada sesi kedua**, atau Anda akan terkunci. Hardening lengkap dibahas di level keamanan.

## 5. Praktik dan Implementasi

**Checklist persiapan**

- [ ] VM lab dengan paket `openssh-server` terpasang dan port 22 terjangkau dari host.
- [ ] Snapshot VM tersedia.
- [ ] Akses konsol VM tersedia sebagai cadangan.

**Langkah**

1. Di komputer klien, buat pasangan kunci dengan passphrase.
2. Salin kunci publik ke VM.
3. Login memakai kunci dari sesi baru.
4. Salin satu berkas ke VM dengan `scp` dan jalankan satu perintah jarak jauh.
5. Pertama kali terhubung, bandingkan sidik jari host dengan yang tampil di konsol VM sebelum mengetik `yes`.

## 6. Perintah Linux

Diuji (versi dan pembuatan kunci pada berkas sementara):

```bash
# pengguna biasa
ssh -V
ssh-keygen -t ed25519 -f ./kunci_demo -C "lab-demo"   # isi passphrase saat diminta
stat -c '%a %n' kunci_demo kunci_demo.pub
```

Pada uji (dengan `-N ""` untuk otomatisasi, hanya pada kunci sekali pakai yang dihapus): `OpenSSH_9.6p1 Ubuntu-3ubuntu13.16`, izin `600` untuk kunci privat dan `644` untuk kunci publik. Pada kunci sungguhan, **jangan** memakai passphrase kosong.

Belum dijalankan penulis (butuh server SSH di VM lab):

```bash
# pengguna biasa, dari komputer klien
ssh-copy-id <PENGGUNA>@<ALAMAT-VM>
ssh <PENGGUNA>@<ALAMAT-VM>
ssh <PENGGUNA>@<ALAMAT-VM> 'uptime'
scp ./catatan.txt <PENGGUNA>@<ALAMAT-VM>:~/
```

## 7. Konfigurasi

Berkas klien yang relevan: `~/.ssh/config` untuk nama pendek, mis. (konsep, belum diuji):

```text
Host lab-mail
    HostName <ALAMAT-VM>
    User <PENGGUNA>
    IdentityFile ~/.ssh/id_ed25519
```

Berkas server: `~/.ssh/authorized_keys` (berisi kunci publik) dan `/etc/ssh/sshd_config`. Setelah mengubah `sshd_config`, validasi sintaks dengan `sudo sshd -t` sebelum `sudo systemctl reload ssh`. Perintah ini belum diuji.

## 8. Verifikasi

- Login dengan kunci berhasil tanpa diminta kata sandi akun (hanya passphrase kunci).
- `ssh <host> 'uptime'` mengembalikan keluaran perintah.
- Berkas yang disalin dengan `scp` tampak di VM.

## 9. Troubleshooting

| Gejala | Penyebab | Tindakan |
|---|---|---|
| `Connection refused` | `sshd` tidak berjalan atau port tertutup | `systemctl status ssh`, `ss -ltn`, aturan firewall |
| `Permission denied (publickey)` | Kunci belum terpasang atau izin salah | Periksa `authorized_keys`, `~/.ssh` 700, kunci 600 |
| `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!` | Host key berubah | Jangan abaikan; pastikan penyebabnya sah (pasang ulang VM) sebelum menghapus entri lama |
| Timeout | Rute/firewall | `CH-02-03-04` untuk diagnosis |

## 10. Security Review

- Gunakan kunci dengan passphrase; kunci privat jangan pernah dibagikan atau dikomit ke repositori.
- Nonaktifkan login root dan kata sandi hanya setelah kunci teruji pada sesi kedua.
- Verifikasi sidik jari host pada koneksi pertama.
- Batasi akses SSH lewat firewall ke alamat tepercaya bila memungkinkan.

## 11. Latihan

1. Buat pasangan kunci ed25519 dengan passphrase dan jelaskan fungsi masing-masing file.
2. Rancang urutan aman untuk menonaktifkan login kata sandi tanpa terkunci.
3. Salin sebuah direktori kecil ke VM dengan `scp -r` dan verifikasi isinya.

## 12. Assessment

1. Berkas mana yang tidak boleh dibagikan, kunci privat atau publik?
2. Di mana kunci publik ditaruh pada server?
3. Mengapa verifikasi sidik jari host penting?
4. Mengapa tidak menonaktifkan kata sandi sebelum menguji kunci?

**Kunci singkat.** (1) Privat. (2) `~/.ssh/authorized_keys`. (3) Mencegah serangan penyamaran server (man-in-the-middle). (4) Bila kunci bermasalah, Anda terkunci.

## 13. Checklist Kelulusan

- [ ] Saya dapat login ke VM memakai kunci SSH.
- [ ] Saya dapat menyalin berkas dan menjalankan perintah jarak jauh.
- [ ] Kunci privat saya aman dan tidak ada di repositori.
- [ ] Saya tidak terkunci dari VM setelah mengubah pengaturan SSH.
