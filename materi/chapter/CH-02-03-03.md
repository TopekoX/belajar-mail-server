## 2. Tujuan Pembelajaran

1. Memahami port, protokol, dan state koneksi.
2. Menerapkan kebijakan firewall deny-by-default tanpa mengunci diri.

## 3. Prasyarat

## 4. Materi Teori

### 4.1 TCP, UDP, dan port

- **TCP** berorientasi koneksi dan andal (dibuka dengan *three-way handshake*: SYN, SYN-ACK, ACK). SMTP, IMAP, POP3, dan SSH memakai TCP.
- **UDP** tanpa koneksi. DNS umumnya memakai UDP (dan TCP untuk jawaban besar).
- **Port** (0–65535) memilih layanan pada satu alamat IP.

| Layanan | Port lazim | Protokol |
|---|---|---|
| SSH | 22 | TCP |
| SMTP (antarserver) | 25 | TCP |
| SMTP submission | 587 (STARTTLS), 465 (TLS langsung) | TCP |
| IMAP | 143, 993 (TLS) | TCP |
| POP3 | 110, 995 (TLS) | TCP |
| DNS | 53 | UDP/TCP |
| HTTP/HTTPS | 80, 443 | TCP |

### 4.2 State koneksi

Firewall *stateful* mengenali status koneksi: `NEW` (koneksi baru), `ESTABLISHED` (sudah terjalin), `RELATED`. Aturan umum: izinkan `ESTABLISHED/RELATED` agar balasan lewat, dan kontrol hanya koneksi `NEW` yang masuk.

### 4.3 Deny-by-default

Kebijakan aman: **tolak semua koneksi masuk**, lalu izinkan hanya yang diperlukan (SSH, kemudian port email sesuai kebutuhan). Keluar umumnya diizinkan pada tahap awal.

### 4.4 UFW dan nftables

- **UFW** (Uncomplicated Firewall) adalah antarmuka sederhana di atas aturan paket Linux, cocok untuk kebutuhan server umum.
- **nftables** (`nft`) adalah kerangka kerja filter paket yang mendasari firewall modern Linux dan memberi kendali rinci.
- Pilih satu alat untuk dikelola; mencampur beberapa pengelola firewall menimbulkan aturan yang membingungkan.

### 4.5 Menghindari penguncian diri

1. Izinkan SSH **sebelum** mengaktifkan firewall.
2. Pastikan Anda punya akses konsol hypervisor.
3. Uji dengan sesi SSH kedua sebelum menutup sesi pertama.
4. Snapshot sebelum perubahan.

## 6. Perintah Linux

Membaca keadaan (aman):

```bash
# pengguna biasa
ss -tuln
```

Mengubah firewall **(belum dijalankan penulis — hanya di VM lab dengan akses konsol)**:

```bash
# root melalui sudo
sudo apt install ufw            # jika belum terpasang
sudo ufw status verbose
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp           # SSH — lakukan SEBELUM enable
sudo ufw enable
sudo ufw status numbered
```

Menghapus aturan: `sudo ufw delete <NOMOR-ATURAN>`. Menonaktifkan darurat (dari konsol): `sudo ufw disable`.

Melihat aturan nftables (hanya baca, butuh root):

```bash
# root melalui sudo
sudo nft list ruleset
```

| Perintah | Fungsi |
|---|---|
| `ufw status verbose` | Status dan kebijakan default |
| `ufw default deny incoming` | Tolak semua masuk secara default |
| `ufw allow <port>/tcp` | Izinkan port tertentu |
| `ufw enable` | Mengaktifkan firewall |
| `nft list ruleset` | Menampilkan seluruh aturan nftables |

## 7. Konfigurasi

Aturan UFW tersimpan dan dikelola lewat perintah `ufw` (jangan edit manual berkas di `/etc/ufw` kecuali memahami format). Contoh rencana aturan awal untuk mail server lab (diaktifkan bertahap, sesuai layanan yang sudah terpasang):

| Port | Tujuan | Kapan dibuka |
|---|---|---|
| 22/tcp | SSH | Sejak awal, sebelum `enable` |
| 25/tcp | SMTP antarserver | Setelah MTA dikonfigurasi dan relay terbukti tertutup |
| 587/tcp | Submission | Setelah autentikasi dan TLS aktif |
| 993/tcp | IMAPS | Setelah Dovecot dan TLS aktif |

## 8. Verifikasi

- `ufw status verbose` menunjukkan `Default: deny (incoming), allow (outgoing)`.
- Dari host lain, port yang diizinkan terbuka dan port lain tidak (pengujian eksternal dibahas di `CH-02-03-04`).
- Sesi SSH kedua dapat terhubung setelah firewall aktif.

## 9. Troubleshooting

| Gejala | Penyebab | Tindakan |
|---|---|---|
| Terkunci keluar SSH | `enable` sebelum mengizinkan 22 | Masuk lewat konsol hypervisor; `ufw allow 22/tcp` atau `ufw disable` |
| Layanan tak terjangkau | Port belum diizinkan | Periksa `ss -tuln` dan aturan UFW |
| Aturan tidak berlaku | Firewall belum aktif atau urutan salah | `ufw status numbered` |
| Konflik aturan | Banyak pengelola firewall | Pakai satu alat saja |

## 10. Security Review

- Terapkan deny-by-default; buka hanya port yang dibutuhkan.
- Membatasi SSH hanya dari alamat tepercaya bila memungkinkan (mis. `ufw allow from <ALAMAT-ADMIN> to any port 22 proto tcp`).
- Firewall melengkapi, bukan menggantikan, konfigurasi layanan yang aman.
- Verifikasi eksposur dari host eksternal, bukan hanya dari server itu sendiri.

## 11. Latihan

2. Tulis prosedur aman mengaktifkan firewall di VM jarak jauh (urutan langkah).

## 12. Assessment

1. Apa arti deny-by-default?
2. Mengapa SSH diizinkan sebelum firewall diaktifkan?
3. Apa beda TCP dan UDP?
4. Port berapa untuk SMTP submission?

**Kunci singkat.** (1) Semua masuk ditolak kecuali yang diizinkan. (2) Agar tidak terkunci. (3) TCP berorientasi koneksi dan andal; UDP tanpa koneksi. (4) 587 (atau 465 untuk TLS langsung).
