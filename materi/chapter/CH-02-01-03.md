# Pengguna, Grup, Izin, dan sudo

!!! info "Identitas chapter"
    **ID:** `CH-02-01-03` · **Kategori/modul:** CAT-02 / MOD-02-01 · **Estimasi:** 120 menit · **Lingkungan:** lab lokal (VM) · [Lihat di dashboard](../../../#CH-02-01-03)

!!! note "Catatan verifikasi"
    Pada 2026-10-13 di Ubuntu 24.04.3 LTS (WSL2) hanya perintah tanpa hak root yang dijalankan: `id`, `stat`, `chmod` pada berkas sementara, dan `getent passwd`. Perintah `adduser`, `usermod`, `sudo`, dan `visudo` **belum dijalankan** penulis karena memerlukan hak root dan mengubah sistem. Jalankan semuanya hanya di VM lab Anda, setelah snapshot.

## 1. Ringkasan

Anda mengelola pengguna dan grup, membaca dan mengubah izin berkas, dan memakai `sudo` dengan prinsip *least privilege*. Mail server akan memakai akun layanan khusus, sehingga pemahaman ini wajib.

## 2. Tujuan Pembelajaran

1. Mengelola user dan grup.
2. Menetapkan izin dan kepemilikan dengan prinsip least privilege.

## 3. Prasyarat

- `CH-02-01-02` — navigasi filesystem.

## 4. Materi Teori

### 4.1 Pengguna dan grup

Setiap proses dan berkas dimiliki oleh pengguna (UID) dan grup (GID). Data pengguna ada di `/etc/passwd` (publik) dan hash kata sandi di `/etc/shadow` (terbatas). Pengguna `root` (UID 0) dapat melakukan apa saja.

Akun *sistem/layanan* (misalnya yang dipakai layanan email kelak) umumnya tidak punya login interaktif.

### 4.2 Izin berkas

Hasil `ls -l` seperti `-rw-r----- root shadow` dibaca sebagai: jenis (`-` berkas, `d` direktori), izin pemilik, grup, dan lainnya (`r` baca, `w` tulis, `x` eksekusi).

| Notasi | Oktal | Arti |
|---|---|---|
| `rw-` | 6 | baca + tulis |
| `r--` | 4 | baca |
| `r-x` | 5 | baca + eksekusi |
| `rwx` | 7 | semua |

Contoh `640` berarti pemilik `rw-`, grup `r--`, lainnya `---`. Pada direktori, `x` berarti boleh masuk/melintasi.

### 4.3 sudo dan least privilege

`sudo` menjalankan satu perintah dengan hak root atas nama pengguna yang diizinkan. Prinsipnya:

- Login sebagai pengguna biasa, gunakan `sudo` hanya saat perlu.
- Jangan login langsung sebagai root.
- Beri hak terbatas lewat berkas di `/etc/sudoers.d/` yang diedit dengan `visudo` (memeriksa sintaks sebelum menyimpan) agar kesalahan tidak mengunci Anda.

## 6. Perintah Linux

Membaca identitas dan izin (diuji):

```bash
# pengguna biasa
id
stat -c '%A %U %G %n' /etc/passwd /etc/shadow /tmp
getent passwd root | cut -d: -f1,3,7
```

Contoh output pada uji:

```text
uid=1000(ucup) gid=1000(ucup) groups=1000(ucup),4(adm),20(dialout),...,27(sudo),...
-rw-r--r-- root root /etc/passwd
-rw-r----- root shadow /etc/shadow
drwxrwxrwt root root /tmp
root:0:/bin/bash
```

Perhatikan: `/etc/shadow` tidak dapat dibaca pengguna biasa, sedangkan `/tmp` ber-*sticky bit* (`t`) sehingga tiap pengguna hanya bisa menghapus berkasnya sendiri.

Mengubah izin berkas latihan (diuji pada berkas sementara):

```bash
# pengguna biasa
chmod 640 berkas.txt
stat -c '%A %a %U %n' berkas.txt
```

Hasil yang diamati: `-rw-r----- 640 ucup demo/a/f.txt` (pada uji nama berkas berbeda).

Mengelola pengguna **(belum dijalankan penulis — hanya di VM lab, setelah snapshot)**:

```bash
# root melalui sudo
sudo adduser <NAMA-PENGGUNA>          # buat pengguna interaktif
sudo adduser <NAMA-PENGGUNA> <NAMA-GRUP>   # tambahkan ke grup yang ada
sudo usermod -aG <NAMA-GRUP> <NAMA-PENGGUNA>
sudo chown <PEMILIK>:<GRUP> berkas.txt
sudo visudo -f /etc/sudoers.d/<NAMA-BERKAS>   # edit aman aturan sudo
```

| Perintah | Fungsi |
|---|---|
| `adduser` | Membuat pengguna (interaktif, dengan home) |
| `usermod -aG` | Menambah ke grup tambahan; `-a` penting agar grup lama tidak terhapus |
| `chmod` | Mengubah izin |
| `chown` | Mengubah pemilik dan grup |
| `visudo` | Mengedit sudoers dengan pemeriksaan sintaks |

## 7. Konfigurasi

Konfigurasi aturan sudo ditempatkan sebagai berkas terpisah di `/etc/sudoers.d/`. Jangan menaruh aturan tanpa `visudo`. Contoh aturan (konsep, belum diuji; gunakan placeholder Anda sendiri):

```text
<NAMA-PENGGUNA> ALL=(root) /usr/bin/systemctl status ssh
```

Aturan di atas hanya mengizinkan satu perintah tertentu sebagai root, bukan semua perintah.

## 8. Verifikasi

- `id` menampilkan grup yang Anda duga.
- `stat` menampilkan izin sesuai `chmod` yang Anda berikan.
- Pengguna latihan tanpa hak sudo tidak dapat menjalankan `sudo` (pesan penolakan muncul).

## 9. Troubleshooting

| Gejala | Penyebab | Tindakan |
|---|---|---|
| `Permission denied` | Pemilik/grup/izin tidak sesuai | Periksa `ls -l`; ubah izin seperlunya, bukan `chmod 777` |
| `sudo: a password is required` | Pengguna tidak memakai sudo tanpa kata sandi | Masukkan kata sandi atau minta hak yang tepat |
| Terkunci karena salah aturan sudoers | Edit manual tanpa `visudo` | Pulihkan dari snapshot; selalu pakai `visudo` |
| Lupa `-a` pada `usermod -G` | Grup lama terhapus | Tambahkan kembali grup yang hilang |

## 10. Security Review

- Hindari `chmod 777`; berikan izin minimum yang diperlukan.
- Jangan login sebagai root; pakai `sudo` seperlunya.
- Kunci privat dan kredensial harus berizin ketat (mis. `600`).
- Hapus pengguna latihan setelah selesai.

## 11. Latihan

## 12. Assessment

1. Apa arti `rw-r-----`?
2. Mengapa memakai `visudo`?
3. Apa risiko `chmod 777`?
4. Apa perbedaan `usermod -G` dan `usermod -aG`?

**Kunci singkat.** (1) Pemilik baca+tulis, grup baca, lainnya tidak ada. (2) Memeriksa sintaks sehingga tidak mengunci sudo. (3) Semua pengguna dapat membaca, menulis, dan mengeksekusi. (4) `-G` menimpa grup tambahan; `-aG` menambahkan.
