# systemd dan Manajemen Service

!!! info "Identitas chapter"
    **ID:** `CH-02-02-01` · **Kategori/modul:** CAT-02 / MOD-02-02 (Service dan Proses) · **Estimasi:** 90 menit · **Lingkungan:** lab lokal (VM) · [Lihat di dashboard](../../../#CH-02-02-01)

!!! note "Catatan verifikasi"
    Pada 2026-10-13 di Ubuntu 24.04.3 LTS (WSL2, systemd sebagai PID 1) hanya perintah baca-saja yang dijalankan: `systemctl is-active/status/is-enabled/list-units` dan `journalctl -u`, terhadap service `cron`. Perintah `start`, `stop`, `restart`, `enable`, dan `disable` **belum dijalankan** penulis.

## 1. Ringkasan

Mail server adalah kumpulan service. Anda belajar memeriksa status service, menjalankan dan menghentikannya, mengatur agar aktif saat boot, dan membaca lognya dengan `systemctl` dan `journalctl`.

## 2. Tujuan Pembelajaran

1. Mengelola siklus hidup service dengan `systemctl`.
2. Membaca log service dengan `journalctl`.

## 3. Prasyarat

- `CH-02-01-05` — dasar shell scripting; Anda nyaman dengan perintah dan `sudo`.

## 4. Materi Teori

### 4.1 Peran systemd

`systemd` adalah proses pertama (PID 1) pada Ubuntu. Ia menjalankan service, mengatur urutan start berdasarkan dependensi, memantau proses, dan mengumpulkan log ke journal. Satuan konfigurasinya disebut *unit* (`.service`, `.socket`, `.timer`, dsb.).

### 4.2 Perintah utama

| Perintah | Fungsi |
|---|---|
| `systemctl status <unit>` | Status ringkas dan log terakhir |
| `systemctl is-active <unit>` | Hanya mencetak `active` atau status lain |
| `systemctl is-enabled <unit>` | Apakah aktif otomatis saat boot |
| `systemctl start/stop/restart <unit>` | Mengubah keadaan service |
| `systemctl reload <unit>` | Memuat ulang konfigurasi tanpa memutus (jika didukung) |
| `systemctl enable/disable <unit>` | Mengatur start otomatis saat boot |
| `journalctl -u <unit>` | Log satu service |

### 4.3 Active vs enabled

`active` berarti sedang berjalan sekarang; `enabled` berarti akan dijalankan saat boot. Keduanya independen: service bisa `enabled` tetapi sedang mati, atau `active` tetapi tidak `enabled`.

### 4.4 Lokasi unit

Unit dari paket ada di `/usr/lib/systemd/system/`. Modifikasi lokal ditempatkan di `/etc/systemd/system/` (misalnya drop-in override) sehingga tidak tertimpa pembaruan paket. Setelah mengubah unit, jalankan `systemctl daemon-reload`.

## 6. Perintah Linux

Baca-saja (diuji pada service `cron`):

```bash
# pengguna biasa
systemctl is-active cron
systemctl is-enabled cron
systemctl status cron --no-pager | head -4
journalctl -u cron -n 2 --no-pager
```

Contoh output pada uji (waktu dan PID berbeda di sistem Anda):

```text
active
enabled
● cron.service - Regular background program processing daemon
     Loaded: loaded (/usr/lib/systemd/system/cron.service; enabled; preset: enabled)
     Active: active (running) since ...
Oct 13 19:07:27 ... cron[160]: (CRON) INFO (pidfile fd = 3)
```

Mengubah keadaan **(belum dijalankan penulis — hanya di VM lab)**:

```bash
# root melalui sudo
sudo systemctl restart cron
sudo systemctl stop cron
sudo systemctl start cron
```

Melihat semua service yang berjalan:

```bash
# pengguna biasa
systemctl list-units --type=service --state=running --no-pager
```

## 7. Konfigurasi

Unit service berada di `/etc/systemd/system` (override lokal) dan `/usr/lib/systemd/system` (bawaan paket). Chapter ini tidak mengubah unit. Prosedur membuat override (konsep, belum diuji): `sudo systemctl edit <unit>`, lalu `sudo systemctl daemon-reload` dan `restart`.

## 8. Verifikasi

- `systemctl is-active cron` mencetak `active`.
- Setelah `stop`, status berubah dan `is-active` tidak lagi `active`; setelah `start`, kembali `active`.
- `journalctl -u cron` menampilkan entri start/stop yang bersesuaian.

## 9. Troubleshooting

| Gejala | Penyebab | Tindakan |
|---|---|---|
| `Unit ... could not be found` | Paket belum terpasang | Periksa nama unit dan paket (`CH-02-01-04`) |
| `failed` | Konfigurasi salah atau port bentrok | `journalctl -u <unit> -n 50`; perbaiki konfigurasi |
| Service tidak jalan setelah reboot | Tidak `enabled` | `sudo systemctl enable <unit>` |
| `degraded` pada `systemctl is-system-running` | Ada unit gagal | `systemctl --failed` untuk melihat unit gagal |

## 10. Security Review

- Hentikan dan nonaktifkan service yang tidak diperlukan.
- Jangan membuka akses ke service sebelum dikonfigurasi; periksa port yang listening (`CH-02-02-02`).
- Batasi siapa yang boleh menjalankan `sudo systemctl` memakai aturan sudoers terbatas.
